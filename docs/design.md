# Дизайн интерфейса FitHome

> Статус: Этап 1 — описание будущего интерфейса. Базовые CSS-переменные уже заложены в `frontend/src/styles/variables.css`; сам интерфейс реализуется начиная с этапа 2.

## 1. Принципы

1. **Мобильный экран — главный.** Тренировка проходит с телефона в руках, поэтому в первую очередь проектируем мобильный вид (от 360 px), затем планшет и десктоп.
2. **Крупные цели управления.** Кнопки «выполнить подход» и чекбоксы упражнений — не менее 44×44 px (доступность, работа с влажными пальцами).
3. **Минимум действий на тренировке.** Во время тренировки пользователь делает не более одного тапа на действие.
4. **Ноль лишних зависимостей.** Чистый CSS: переменные `:root`, адаптивные сетки (flex/grid), media queries. Без CSS-фреймворков.
5. **Тёмная и светлая темы.** Все цвета — через переменные; тема `system` следует `prefers-color-scheme`.

## 2. Структура приложения (SPA)

Единая точка входа — `frontend/src/App.tsx`. Маршруты (React Router — добавляется на этапе 2):

| Путь | Экран | Доступ | Этап |
|---|---|---|---|
| `/login`, `/register` | Вход и регистрация | публичный | 2 |
| `/` | Дашборд: активная программа, ближайшая тренировка, сводка за неделю | auth | 2–4 |
| `/programs` | Список программ | auth | 3 |
| `/programs/:id` | Состав программы, редактирование | auth | 3 |
| `/exercises` | Каталог упражнений с фильтрами по месту и группам мышц | auth | 3 |
| `/workouts` | История тренировок (календарь/список) | auth | 4 |
| `/workouts/:id` | Детали тренировки и результаты | auth | 4 |
| `/workout-session/:programId` | Активная тренировка: прохождение программы | auth | 4 |
| `/stats` | Статистика и прогресс | auth | 4 |
| `/settings` | Настройки пользователя | auth | 5 |

Навигация: на мобильном — нижний таб-бар (4 пункта: Дашборд, Программы, История, Профиль); на десктопе — боковое меню.

## 3. Ключевые экраны

### 3.1. Дашборд (`/`)

- Приветствие с именем пользователя.
- Карточка активной программы: название, прогресс по неделям, кнопка «Начать тренировку».
- Мини-сводка недели: количество тренировок, суммарные подходы (данные из `GET /api/stats/summary`).
- Быстрые действия: «Свободная тренировка», «Создать программу».

### 3.2. Каталог упражнений (`/exercises`)

- Поиск по названию (параметр `search` из [api.md §3](api.md#3-упражнения--apiexercises)).
- Фильтры-чипы по месту: `home` / `outdoor` / `gym`.
- Карточка упражнения: название, иконка места, группы мышц, тип метрики (повторы / вес / время).
- Кнопка «+» — создание персонального упражнения (модальное окно).

### 3.3. Состав программы (`/programs/:id`)

- Упорядоченный список упражнений: порядковый номер, название, целевые `sets × reps` или время, drag-handle для изменения порядка.
- Добавление упражнения — выбор из каталога с поиском.
- Задание целей: подходы, повторы/вес/время — форма учитывает метрику упражнения (`Exercise.metric`).

### 3.4. Активная тренировка (`/workout-session/:programId`)

Центральный экран приложения — проектируется с особым вниманием:

- Список упражнений программы сверху вниз, каждое — свёрнутая строка; активное упражнение раскрыто.
- Счётчик подходов: крупная кнопка «Выполнить подход» — увеличивает счётчик; повторы/вес вводятся быстрыми степперами ±.
- Прогресс-бар тренировки (выполнено упражнений / всего).
- Кнопка «Завершить» — сохранение `POST /api/workouts` одним запросом (результаты накапливаются локально в состоянии).
- Работа офлайн-устойчиво: если сеть недоступна, результаты сохраняются в localStorage и отправляются при восстановлении (реализация — этап 4).

### 3.5. История и детали тренировки (`/workouts`, `/workouts/:id`)

- Список с группировкой по датам: место (иконка), программа, количество упражнений.
- Детали: таблица результатов, заметки, кнопка «Повторить тренировку» (создаёт новую сессию из той же программы).

### 3.6. Статистика (`/stats`)

- Сводка за период (неделя/месяц/выбор дат): тренировки, подходы, повторы, объём веса.
- График прогресса по выбранному упражнению (линейный график из `GET /api/stats/exercises/:id`; рисуется SVG без библиотек).

### 3.7. Настройки (`/settings`)

- Единицы веса: кг / фунты.
- Тема: светлая / тёмная / системная.
- Напоминание: время `HH:mm`, переключатель вкл/выкл.
- Выход из аккаунта.

## 4. Визуальный язык

### 4.1. Цвета (CSS-переменные — `frontend/src/styles/variables.css`)

| Переменная | Светлая тема | Назначение |
|---|---|---|
| `--color-primary` | `#2f6fed` | Основные действия, ссылки |
| `--color-primary-hover` | `#1e5be0` | Hover/active состояний |
| `--color-success` | `#22a55f` | Выполненные подходы, положительная динамика |
| `--color-danger` | `#e0482f` | Удаление, ошибки |
| `--color-warning` | `#f0a13c` | Предупреждения |
| `--color-bg` | `#f5f6fa` | Фон приложения |
| `--color-surface` | `#ffffff` | Карточки, панели |
| `--color-text` | `#1c2333` | Основной текст |
| `--color-text-muted` | `#697086` | Второстепенный текст |
| `--color-border` | `#e2e5ec` | Границы, разделители |

Тёмная тема переопределяет переменные селектором `[data-theme="dark"]` (значения задаются на этапе 2; механизм заложен уже сейчас).

### 4.2. Типографика

- Шрифт: системный стек (`system-ui, -apple-system, Segoe UI, Roboto, sans-serif`) — без загрузки внешних шрифтов.
- Базовый размер 16 px; заголовки: `--font-size-h1` 24 px, `--font-size-h2` 20 px; вспомогательный текст 14 px.
- Числовые показатели (счётчики подходов) — 32 px, жирные.

### 4.3. Отступы, радиусы, тени

- Переменные отступов: `--space-1` (4 px) … `--space-5` (32 px), шаг ×2.
- Радиусы: `--radius-s` 8 px (поля ввода), `--radius-m` 12 px (карточки), `--radius-l` 16 px (модальные окна).
- Тень карточки: `--shadow-s`; модального окна: `--shadow-l`.

### 4.4. Адаптивность

| Контрольная точка | Поведение |
|---|---|
| ≥ 360 px (мобильный) | Одна колонка, нижний таб-бар |
| ≥ 768 px (планшет) | Списки в две колонки, таб-бар уходит вниз экрана как подвал |
| ≥ 1024 px (десктоп) | Боковое меню (240 px), контент максимум 1200 px по центру |

## 5. Компонентная база (этапы 2–4)

Минимальный набор переиспользуемых компонентов (`frontend/src/components/`):

| Компонент | Назначение |
|---|---|
| `Button` | Варианты: primary, secondary, danger; размеры |
| `Card` | Контейнер-карточка |
| `TextField` | Поле ввода с валидацией и сообщением об ошибке |
| `Select` | Выпадающий список (место, метрика) |
| `Chip` | Фильтры-чипы |
| `Modal` | Модальные окна (создание упражнения, подтверждение удаления) |
| `Spinner` | Индикатор загрузки |
| `EmptyState` | Заглушка пустых списков («Создайте первую программу») |
| `ProgressBar` | Прогресс тренировки/программы |
| `Stepper` | Быстрый ввод числа (повторы, вес ±) |

Каждый компонент получает стили через CSS-файл с тем же именем (путь к CSS Modules будет выбран на этапе 2).

## 6. UX-потоки

### 6.1. Регистрация → первая тренировка

1. `/register` → форма email/пароль/имя → `POST /api/auth/register` → дашборд.
2. Дашборд пуст → `EmptyState` предлагает «Создать программу».
3. Программа создана → добавление упражнений из каталога → задание целей.
4. «Начать тренировку» → активная тренировка → выполнение подходов → «Завершить» → детали тренировки.

### 6.2. Ошибки и состояния

- Каждая форма показывает inline-ошибки валидации и ошибки сервера (`error.message` из [api.md §1](api.md#1-общие-положения)).
- Загрузка данных — `Spinner`; пустые списки — `EmptyState`; сетевые ошибки — баннер с кнопкой «Повторить».
- Истечение access-токена прозрачно: HTTP-клиент повторяет запрос после `/api/auth/refresh`; при отказе — редирект на `/login`.

## 7. Доступность

- Семантические теги (`button`, `nav`, `main`, `label`).
- Контраст текста ≥ 4.5:1 (проверяется для обеих тем).
- Фокус-кольца на всех интерактивных элементах (`:focus-visible`).
- Полная навигация с клавиатуры.
